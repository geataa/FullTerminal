# FullTerminal 1.1.0 — Databases, SQL and reliability fixes

FullTerminal now brings native database connections and SQL editing into its C++20 Windows workspace. **[Claude](https://github.com/claude) established the initial architecture**, and Antigravity continued development on that foundation. **OpenAI Codex then took over where Antigravity left off**, reviewed the existing implementation, fixed reported bugs and added the database features under geataa's direction.

## Database and SQL workspace

- Each main tab owns a connection; tables and SQL editors open as subtabs.
- Embedded SQLite, plus PostgreSQL, SQL Server, MySQL/MariaDB, Oracle and generic ODBC/DSN adapters using installed 64-bit drivers.
- Database/schema/table/view browsing, column and primary-key metadata, server-side sorting, filtering and paging for supported dialects.
- Parameterized insert/update/delete, NULL and DEFAULT handling, conflict checks and transaction controls.
- SQL highlighting, selection execution, undo/redo, UTF-8 script files, multiple result sets, cancellation and in-memory execution history.
- CSV/JSON export of fetched results and numeric bar charts.
- Connection health checks, explicit reconnect after failure, preserved editor contents and results, and DPAPI-protected saved passwords. Interrupted writes are never automatically replayed.

## Bug fixes and completed integrations

- Preserve terminal themes, ANSI state, transparency and cursor behavior across normal, maximized and Quake window transitions.
- Repair text-field copy/paste and selection; double-click terminal tokens to select and copy them.
- Keep SSH loading visible until terminal readiness is detected, while exposing password and host-key prompts for input.
- Use stable Hub names for tabs, with numeric suffixes for duplicates and support for manual renaming.
- Prevent stale SFTP folder listings after asynchronous navigation.
- Launch WSL distributions and docker-desktop consistently from both the + menu and Systems & Hub; remove duplicate context-menu icons.
- Improve persistent-session detach/reattach, resize and process-exit handling.
- Integrate recording playback and authenticated loopback MCP HTTP transport.
- Use one application version across the UI, MCP server, manifest and Windows executable metadata. The executable remains **FullTerminal.exe**.

## Validation and scope

The Windows regression suite contains **19 tests**, including actual Win32 rendering/input, SQLite/database UI, SSH loopback, SFTP navigation, daemon reconnect and MCP HTTP. PostgreSQL 16.14 with psqlODBC 18.00.0004 was also exercised against a disposable live server for metadata, Unicode CRUD, transactions, cancellation and connection loss/reconnect. Both WSL launch paths were checked with Ubuntu and docker-desktop.

SQL Server, MySQL/MariaDB and Oracle adapters compile but have not yet been verified against live servers. Their matching 64-bit ODBC drivers must be installed separately. Advanced visual schema/role designers, ER diagrams, backup/restore/import wizards and SQL autocomplete are not included. New database labels currently provide English and Turkish text.

## Downloads and upgrade

- **FullTerminal.exe** — portable Windows x64 application; SQLite is embedded.
- **FullTerminal-v1.1.0-windows-x64.zip** — executable, README, release notes, project license and SQLite provenance.
- **FullTerminal-Portable-x64.zip** — the same ZIP under a stable download name.
- **SHA256SUMS.txt** — checksums for the executable and ZIP.

Exit FullTerminal completely before replacing the executable, then launch the new **FullTerminal.exe**. Keep your adjacent `portable_data` folder to retain settings. OpenSSH, WSL, Docker, kubectl and server ODBC drivers are required only for their respective features. DPAPI secrets remain tied to the Windows account that saved them.
