# FullTerminal 1.1.1 — Built-in database clients

PostgreSQL, MySQL/MariaDB and SQL Server now connect through client libraries statically linked into **FullTerminal.exe**. These engines no longer require a separate ODBC driver installation. No database server or background service is installed.

## Changes

- Built-in libpq 18.6, MariaDB Connector/C 3.4.11 and FreeTDS 1.5.19 clients; their dependencies use the static Windows runtime. SQLite remains embedded.
- Existing PostgreSQL, MySQL and SQL Server profiles use their native adapter automatically. Their connection form saves without an ODBC driver or DSN. Generic ODBC remains an optional external-driver path; Oracle is outside the built-in engine scope.
- TLS certificate verification with Windows trust roots or a supplied PEM CA file. Disabling encryption or trusting an unverified certificate requires an explicit profile choice; there is no silent plaintext fallback.
- Native table/column/primary-key/generated-column discovery, parameterized grid editing, conflict detection, transactions and savepoints. Each main tab still owns one connection; tables and SQL editors remain subtabs.
- Bounded results, cancellation, connection-loss detection and explicit reconnect. Interrupted writes are never automatically replayed. Saved passwords remain protected by Windows DPAPI.
- Pinned client sources, license notices and rebuild/relink sources accompany the release. The build keeps downloaded dependencies in the project directory and uses the same CMake source list for development and release.
- Fix intermittent MCP HTTP connection resets when rejecting a request before its body arrives; clients reliably receive the rejection response. Clean builds also create the missing output directory before publishing the executable.

## Validation and current limits

**20 Windows regression suites passed**, including database logic, real Win32 form interaction and saving a native profile without an installed driver. Executable import inspection found only Windows system DLL dependencies.

The native PostgreSQL client was tested against an existing live server using only a session-local temporary table: authentication, metadata, Unicode/emoji, NULL versus empty text, decimal values, parameterized CRUD, row limits, multiple results, conflict rollback, savepoints, cancellation, connection loss and reconnect. No existing application tables were modified.

MySQL/MariaDB and SQL Server passed compilation and connection failure-path tests; **live-server compatibility has not yet been verified for those two adapters**. MySQL cancellation closes its connection and requires reconnect. Built-in MySQL authentication covers native password, SHA-256 and caching SHA-256; Ed25519, PARSEC and GSSAPI plugins are not bundled. SQL Server Windows authentication depends on the server/domain configuration; use a login with read-only grants when permission enforcement is required. PostgreSQL streaming COPY is not supported in the result grid.

## Downloads and upgrade

- **FullTerminal.exe** — Windows x64 portable application with the client libraries inside.
- **FullTerminal-v1.1.1-windows-x64.zip** — executable, documentation, release notes and licenses. Matching rebuild sources are available separately below.
- **FullTerminal-Portable-x64.zip** — the same portable package with a stable download name.
- **FullTerminal-Rebuild-Sources.zip** — application source, vendored library sources and build recipes for rebuilding/relinking.
- **SHA256SUMS.txt** — checksums for all downloadable binaries and archives.

Exit FullTerminal completely before upgrading; preserve the adjacent `portable_data` directory. Launch the new **FullTerminal.exe**. All application version fields are **1.1.1** (Windows file metadata: **1.1.1.0**).
